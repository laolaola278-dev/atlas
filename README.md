# Atlas 医疗智能体临床协作平台

> **当前角色**：项目负责人
> **本章产出**：仓库导航与第一轮交付索引
> **依赖的上游产出**：只读策划附件、`plan/_contract.md`

Atlas 是面向医疗机构的**临床协作、文书、审核与可审计层**。本平台不做自主诊断决策、不做自动处方、不替代执业医师；所有 AI 输出均为建议，必须经人工签核方可进入病历或医嘱。原始诊疗数据遵循**数据不出院**原则，院外仅允许经批准的脱敏聚合指标。

开发原则：**患者安全 > 合规 > 正确性 > 可观测性 > 性能 > 代码量**。

## 目标阶段

1. **P0**：契约、工程骨架、CI、FHIR Profile 与术语清单。
2. **P1**：FHIR、术语、EMPI。
3. **P2**：HL7/DICOM 接入与实时生理流。
4. **P3**：CDSS、确定性规则、HITL 强制签核、可解释性。
5. **P4**：结构化文书、医保“两库”、排班。
6. **P5**：临床评测、漂移监控、强制停用。
7. **P6**：审计、隐私、知情同意。
8. **P7**：医生工作站、审核台、SDK、信创交付。
9. **P8**：压测、安全、混沌、文档与合规门禁。

## 不可妥协的工程约束

- 未签核建议无法通过状态机、数据库约束和服务/API 证明进入病历或医嘱。
- 药物相互作用、禁忌、剂量上限等硬规则只走确定性规则引擎，不交给 LLM。
- 证据链必须指向具体指南条目、检验值和时间点，禁止“模型认为”。
- 每次数据访问记录 who / when / what / why；why 不可为空。
- CI、单元测试和压测只使用带 `synthetic=true` 的纯合成数据。经伦理批准的去标识化数据不得进入性能环境；`phi-scan` 命中即失败。
- 急诊与常规资源隔离；急诊目标 RPO 0、RTO < 60s。
- 未验证的外部标准、法规、市场数字均标记 `[待验证]`，不得伪装为已核验事实。
