# Atlas 第一轮实施里程碑与量化门禁

> 当前角色：医疗信息化首席架构师、临床信息学负责人、测试架构师与 SRE 负责人
> 本章产出：P0–P8 的批次边界、LOC 口径、退出门禁、证据包与失败处置
> 依赖的上游产出：冻结的产品定位、ADR-001 至 ADR-032、容量模型、八项压测剧本和共享批次契约

## 1. 统一计量口径

1. 实施批次共 **384 条**，ID 从 `ATLAS-P0-0001` 连续到 `ATLAS-P8-0384`；依赖只允许引用更小 ID。
2. 单批手写代码目标为 **800–2,500 行**；阶段增量之和为 **28,000 + 86,000 + 60,000 + 106,000 + 94,000 + 24,000 + 66,000 + 76,000 + 20,000 = 560,000 行**。
3. 生产代码与测试代码分别记账，目标为 **350,000 + 210,000 = 560,000 行**；生成代码、展开清单和第三方制品单列，不进入手写行数。
4. 阶段退出必须同时满足代码门禁、临床安全门禁、隐私安全门禁和可复核证据门禁；任一硬门禁失败即停止进入下一阶段。
5. 所有性能数字均来自可复现实验，报告中同时保留硬件规格、数据规模、协调遗漏修正、预热策略、原始结果与算式。

## 3. 各阶段专项量化检查

### P0：契约优先与可构建性

- `go build ./...`、前端类型检查、Python 类型检查和 Java 编译均返回 0。
- protobuf、OpenAPI、AsyncAPI 的破坏性差异为 0；新增导出符号文档注释覆盖率为 100%。
- FHIR Profile、Extension、术语系统及版本必须可被 CI 枚举，禁止在业务代码中硬编码未登记编码。
- 真实患者数据扫描覆盖源码、测试、fixture、示例、文档和构建上下文；任何高置信命中使流水线失败。

### P1：互操作与身份解析

- EMPI 容量公式：`26 × 500,000 = 13,000,000 ≥ 10,000,000`，保留 30% 容量余量。
- 消歧报告按准确匹配、概率匹配和人工复核三层拆分，不以总体准确率掩盖高风险子集退化。
- FHIR 查询容量公式：32 台仅 `32 × 8,000 = 256,000 QPS`，不足以覆盖 MP-01 的 260,000 QPS；按 30% 可用余量至少 `ceil(260,000 ÷ (8,000 × 0.70)) = 47` 台。检索报告还必须明确“100 万”是旅程、单个请求还是同时在途调用，并分别复核顺序/并发 Little 定律结果。

### P2：设备与接入链路

- 设备容量公式：`6 × 250,000 = 1,500,000 点/秒 ≥ 1,000,000 点/秒`。
- MP-02 场景在 2 小时内建索引 1,000,000 名新患者，自动消歧准确率 ≥ 99.9%，错误合并为 0。
- 5 分钟时钟漂移、网络分区 30% 丢包、磁盘写满和术语不可用均须有明确降级；术语不可用时拒绝生成建议。

### P3：临床安全与人工签核

- 合法普通路径仅为 `draft → pending_review → approved → committed` 的写回资格投影；抢救路径必须进入独立的 `break_glass → emergency_pending_confirmation → post_review_required → reconciliation_confirmed` 链，完成后只归档紧急事实，不得回到普通写回路径。
- 绕过测试至少覆盖直调数据库、伪造状态、重放旧签核、修改建议后复用签核、跨患者提交、过期证书、并发双写和前端参数篡改。
- 药物相互作用、禁忌、剂量上限、过敏和重复用药由确定性规则判定；模型不得改变硬规则结论。
- 每条解释必须定位到指南条目、检验值、药物或医嘱及时间点；证据无法解析时系统拒答。

### P4：文书与院内运营

- 文书先通过结构化 Schema、术语绑定、来源接地和隐私过滤，再由具备授权的审核者签核。
- 文书容量公式：`10,000 ÷ 3,600 ≈ 2.78 份/秒`；稳态测试至少持续 8 小时，P95 < 20 秒。
- 医保两库规则须同时保存来源、地区、知识版本、生效期、失效期和冲突优先级；DRG/DIP 差异不得隐藏在代码常量中。

### P5：临床有效性

- 评测集至少 2,000 例，包含阴性对照、困难阴性、亚组和多院区样本；训练、调参和最终评测数据严格隔离。
- 关键提醒同时报告召回率、假阳性率、阳性预测值、置信区间、亚组差异和病例构成。
- 漂移、临床反馈或不良信号越界后，5 分钟内阻断新建议生成；已生成建议保留证据并进入人工复核。

### P6：可审计与隐私

- 审计容量公式：`104 × 25,000,000 = 2,600,000,000 条/天 ≥ 2,000,000,000 条/天`。
- 每次访问必须记录 who、when、what、why、purpose、consent_decision、source_trace；why 为空即拒绝访问。
- 哈希链按分片和检查点验证，SM2 签名、SM3 摘要、WORM 保留策略和第三方校验接口在同一演练中验证。
- 去标识化同时评估 k 匿名、唯一性、再识别成功率和属性泄露；再识别率目标为 < 0.1%。

### P7：临床工作流与私有化

- 审核台硬门禁统计从任务/证据加载开始到提交持久化回执的端到端 P99 < 500ms；服务端提交、证据读取和页面渲染子指标另列，不能用子指标替代硬门禁。
- 离线交付从校验镜像开始计时，2 小时内完成安装、配置、数据库迁移、健康检查与回滚演练。
- 界面断线、模型超时、术语不可用或审计写入失败时进入可见降级状态，不允许伪装为成功。

## 4. 全局发布门禁

以下条件必须同时成立才可从 P8 进入候选发布：

1. 手写 SLOC 精确达到 560,000，生产与测试分别为 350,000 和 210,000；相似度超过 90% 的重复块为 0。
2. 非平凡函数占比 ≥ 60%；单文件 ≤ 800 行、单包 ≤ 8,000 行；导出符号文档注释覆盖率 100%。
3. 单元行覆盖 ≥ 85%、分支覆盖 ≥ 75%；EMPI、FHIR 校验、规则引擎、HITL、审计核心包覆盖率 ≥ 95%。
4. 属性测试每项 ≥ 5,000 次零反例；竞态检测为 0；集成场景 ≥ 2,500；FHIR 官方校验通过率 100%。
5. 模糊测试 ≥ 1,000 核时且零新增崩溃；核心包变异杀死率 ≥ 70%；安全高危漏洞为 0。
6. 可用性目标 ≥ 99.95%，急诊链路 ≥ 99.99%；急诊演练 RPO = 0、RTO < 60 秒。
7. 真实患者数据检测覆盖全部仓库与制品；CI、日志、截图、fixture、文档和压测数据均不得含真实患者数据。
8. 32 项 ADR、FMEA ≥ 30 条、运行手册、回滚手册、等保三级证据矩阵和密评证据矩阵全部完成双向追踪。
