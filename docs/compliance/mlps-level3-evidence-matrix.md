# Atlas 等保三级控制与证据矩阵

> **当前角色**：隐私与安全负责人
> **本章产出**：等保三级建设控制项、Atlas 实现映射和审计证据索引
> **依赖的上游产出**：`plan/_contract.md`、`docs/adr/ADR-012..015.md`、`docs/adr/ADR-020.md`、`docs/adr/ADR-022..026.md`

## 1. 适用边界

本矩阵是工程交付索引，不替代主管机关、测评机构或法律意见。附件所列 2025–2026 年政策、标准与市场数字均需在正式申报前由合规负责人核验原文、适用范围、发布日期和有效状态，统一标记 `[待验证]`。

Atlas 原始诊疗数据必须在院内闭环；云端仅接收经批准的去标识化聚合指标。跨境传输才进入数据出境评估。境内跨院区临床查询按 ADR-021 的最小必要例外审批，运维导出按目的、字段和留存期做分级合规评估，三者不得混称出境。

## 4. 证据包结构

每次合规构建生成只读证据包：

```text
compliance-evidence/
  manifest.json
  sbom.cdx.json
  image-signatures.json
  control-results.json
  access-matrix.json
  phi-scan.json
  vulnerability-report.json
  restore-drill.json
  hitl-bypass-report.json
  approvals/
```

`manifest.json` 必须记录 Git 提交、构建时间、制品摘要、工具版本、策略版本和审批人。制品使用 Cosign 签名；证据摘要写入 WORM。

## 5. 交付门禁

1. 高危漏洞为 0；无法升级的例外必须有风险接受、到期日和补偿控制。
2. 未签核建议写入尝试必须 100% 被拒绝并产生审计事件。
3. 审计链任意字节篡改必须被检测；WORM 归档不可覆盖。
4. 去标识化数据集再识别率 < 0.1%，评测报告包含攻击模型和置信区间。
5. PHI 扫描在 CI 中 fail-closed；测试和压测数据必须标记合成来源。
6. 备份恢复和急诊故障切换演练必须在交付前成功。
7. 所有 `[待验证]` 法规、标准、指南声明在提交监管材料前清零或改为有证据引用。

## 6. 证据判定

| 结果 | 判定 |
|---|---|
| 控制实现存在且自动证据通过 | 通过 |
| 控制实现存在但证据过期 | 条件通过，必须限期复测 |
| 只有设计文档、无运行证据 | 不通过 |
| 人工复核缺失且涉及患者数据 | 不通过 |
| 工具扫描异常或被绕过 | 阻断发布并启动安全事件 |
