# ADR-007：CDSS 硬规则与 LLM 的职责边界

## 文档头

| 项目 | 内容 |
|---|---|
| 状态 | 已接受（首轮规划） |
| 日期 | 2026-09-24 |
| 当前角色 | 临床决策支持架构师 / Go 平台负责人 |
| 本章产出 | 药物相互作用、禁忌和剂量上限的确定性执行边界及降级策略 |
| 依赖的上游产出 | 主提示词 §4.1、§4.2 ADR-007、§5 技术栈 |
| 关联 ADR | ADR-001、ADR-008、ADR-009、ADR-010、ADR-016、ADR-018 |

## 背景

CDSS 同时面对可枚举、可版本化的安全规则与需要语言归纳的临床信息。药物相互作用、禁忌和剂量上限一旦遗漏或被语言模型误判，可能直接伤害患者；把确定性规则与 LLM 混在同一不可解释路径中也会破坏测试、复现和回滚。反之，要求 LLM 逐字复述规则并不能替代规则引擎，反而可能产生遗漏。

## 选项对比

| 方案 | 硬规则 | 解释性 | 回归测试 | 结论 |
|---|---|---|---|---|
| A：全部交给 LLM | 实现灵活 | 低 | 难穷举 | 医疗安全红线，拒绝 |
| B：全部硬编码规则 | 可重复 | 高 | 清晰 | 表达自然语言与新场景成本高 |
| C：确定性引擎裁决，LLM 仅做已验证事实的归纳/文书 | 安全边界清楚 | 可引用证据 | 规则可穷举 | **采用** |

## 决策

### 1. 能力分区

| 能力 | 执行组件 | 允许的输出 | 禁止行为 |
|---|---|---|---|
| 药物相互作用 | 药物知识库 + 确定性规则 | 命中规则、严重级别、证据、建议复核 | LLM 自行判断存在/不存在相互作用 |
| 禁忌 | 患者状态/年龄/妊娠等事实 + 规则 | 命中条件及来源 | 用语言相似度替代逻辑条件 |
| 剂量上限 | 剂量规则 + 单位标准化 + 人口学事实 | 超限、边界、证据 | 默认填入“常用剂量”后继续 |
| 指南归纳 | LLM | 对已批准规则/报告的结构化摘要 | 创造新规则、删除限定条件 |
| 文书草稿 | LLM + JSON Schema | 供人工审阅的草稿 | 自由文本直接入病历 |
| 未识别情况 | 规则引擎 | 明确 `UNKNOWN/REVIEW_REQUIRED` | 猜测安全结论 |

### 2. 确定性执行链

```text
规范化临床事实
  → 数据完整性/时效检查
  → 规则适用性筛选
  → 条件求值
  → 冲突消解与安全合并
  → 生成 RuleDecision（机器可判定）
  → 证据链
  → 可选的 LLM 文案生成
  → 人工签核状态机
```

`RuleDecision` 是不可被 LLM 改写的结构化对象，至少包含 `rule_id`、`rule_version`、输入事实引用、命中条件、计算中间值、结果、严重度、证据、有效期、规则集摘要和引擎版本。LLM 文案必须逐字段绑定该对象；Schema 校验失败则丢弃文案，但不影响结构化裁决保留。

事实缺失不等价于“未命中”。对硬规则所需字段缺失时返回 `INDETERMINATE`，阻断需要该规则的临床写入或显式进入人工队列。规则超时、依赖库不可用或版本不完整时必须 fail-closed；不得用 LLM 补答。

### 3. 规则包与冲突处理

| 冲突类型 | 消解规则 |
|---|---|
| 同一事实多个规则 | 全部保留，生成去重后的命中集合 |
| 同等级建议冲突 | 不自动相互抵消，升级人工复核 |
| 严级与低级别冲突 | 保留严级，不因低级别命中而移除 |
| 规则版本重叠 | 只加载一个已批准活动集；迁移按生效时间选择 |
| 证据过期 | 结果 `EXPIRED/INDETERMINATE`，不得签核为当前有效 |
| 单位无法唯一转换 | `INDETERMINATE`，进入隔离 |

每次运行记录规则集内容摘要，不能只记 Git 分支。规则内容、发布日期、来源、审批人、变更差异和回滚包均不可变。临床规则由相应专业委员会批准；具体规则医学正确性为 `[待验证]`。验证方法：对每条规则执行正例、负例、边界例、与相邻规则组合的属性测试，并做专家盲审和知识库对拍。

### 4. LLM 输出约束

LLM 只能读取最小必要事实、批准的指南摘录和 `RuleDecision`，不得写回规则库。提示模板、模型版本、输入事实摘要和输出 Schema 版本均进入审计。输出被裁剪、引用缺失、限定条件变化或引用版本不符时，结构化降级为“仅显示规则结论，请按原始证据审核”，并标记文案不可用。

## 可复算推导

规则集覆盖门禁可按下式计算：

`coverage = tested_rule_condition_pairs / declared_rule_condition_pairs`

若声明 8,000 个规则—条件组合，测试 7,920 个且每个至少覆盖正、负、边界 3 类：

`7,920 / 8,000 = 99%`

但安全关键规则要求 100%，因此 `8,000 - 7,920 = 80` 个未覆盖组合均为发布阻断项；不得用整体 99% 掩盖。每条规则还计算：

`rule_digest = SHA-256(canonical_rule_bytes)`

并与签名发布清单比对。具体规则数、规则实现和 Go/Rego 组合能力为 `[待验证]`。验证方法是从规则声明自动生成覆盖清单，运行不少于 5,000 次属性试验/属性，并做规则包模糊测试和签名清单核对。

审核台计算延迟可用：

`t_end_to_end = t_fact + t_rule + t_LLM(optional) + t_render`

例如 `t_fact=80 ms、t_rule=40 ms、t_LLM=8 s、t_render=30 ms`，则总计 `8,150 ms`；对 20 秒 P95 文书目标，尚有 11,850 ms 理论余量，但不能据此宣称 P95 已达标。分项耗时为 `[待验证]`，须用目标硬件和真实分布的合成数据做基准。

## 安全后果

- 确定性引擎提高可重复性，但规则覆盖不完整会产生“未命中”的假安全感；未知状态、规则覆盖率与到期必须显式展示。
- LLM 不裁决硬规则，残余风险转向事实质量、规则内容和版本选择，均需独立治理。
- fail-closed 保证知识库故障时不静默放行，但会增加临床工作流负担，应提供受控降级而非猜测。
- 规则建议仍需人工签核，引擎不直接创建医嘱。

## 回滚方案

1. 规则包发布异常时，原子切换至上一已签名活动集；正在执行的建议按旧/新版本保留，不重解释历史结果。
2. 引擎故障时保留 `RuleDecision=INDETERMINATE`，暂停依赖建议的签核；不得临时启用 LLM 裁决。
3. LLM 文案异常时仅禁用文案生成，结构化规则结果和证据继续显示。
4. 回滚验收包括全部规则回归、摘要对账、未决版本差异为零、双版本选择测试和紧急停用演练。
