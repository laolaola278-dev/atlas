# ADR-008：可解释性证据链

## 文档头

| 项目 | 内容 |
|---|---|
| 状态 | 已接受（首轮规划） |
| 日期 | 2026-09-24 |
| 当前角色 | 临床信息学顾问 / 可解释性架构师 |
| 本章产出 | 建议到具体指南条目、检验值和时间点的可计算证据链 |
| 依赖的上游产出 | 主提示词 §4.1、§4.2 ADR-008、§4.5 |
| 关联 ADR | ADR-001、ADR-004、ADR-007、ADR-009、ADR-014、ADR-018 |

## 背景

医疗人员需要判断“这条建议为何出现”，而不是阅读无法追溯的模型叙述。禁止“模型认为”式解释：每条结论必须落到可定位的指南条目、具体检验值、单位、参考区间、采样/报告时间，或具体规则条件。解释既要面向临床人员可读，也要面向机器逐项验证，并能随规则、知识、模型和患者数据版本重放。

## 选项对比

| 方案 | 临床可读性 | 机器验证 | 历史重放 | 结论 |
|---|---|---|---|---|
| A：自然语言免责声明 | 高表面可读 | 低 | 低 | 拒绝 |
| B：只给参考文档链接 | 中 | 定位不稳定 | 版本易漂移 | 拒绝 |
| C：结构化证据 DAG + 确定性解释模板 + 版本锁定 | 高 | 高 | 可重放 | **采用** |

## 决策

### 1. 证据链数据模型

每条建议的 `ExplanationEnvelope` 至少包含：

| 字段 | 含义 |
|---|---|
| `explanation_id` | 稳定标识 |
| `suggestion_id/version` | 绑定具体建议版本 |
| `claim_id` | 单个可验证声明 |
| `claim_text` | 不增加新医学结论的临床表述 |
| `evidence_type` | 指南、规则、检验、用药、诊断、时间线、状态等 |
| `source_ref` | 稳定 ID、URI、页/节/条目、版本、发布日期 |
| `source_digest` | 原始证据内容摘要，防止链接漂移 |
| `fact_ref` | 患者事实 ID、字段、单位、值、参考区间、时间 |
| `derivation` | 条件、比较、计算式、中间值 |
| `validity` | 事实采集时间、有效期、时区 |
| `model/rule/template_version` | 参与生成的各版本 |

证据以有向无环图组织：原始来源与患者事实为叶，规则判定与校准为中间节点，建议与展示文案为根。节点必须被签名或纳入不可变事件；删除任一被引用节点需引用其替代版本，不能破坏历史链。

### 2. 强制证据类型

| 结论类型 | 最低证据 | 禁止替代 |
|---|---|---|
| 药物相互作用/禁忌/剂量 | 规则 ID/版本、完整适用条件、药品与患者事实、具体来源 | “类似药物通常……” |
| 检验相关建议 | 检验项目、数值、单位、参考区间、采样/报告时间、趋势时点 | “检查异常” |
| 指南建议 | 标题、发布方、版本、页/章节/条目、适用人群和限定条件 | 只有网址或文档标题 |
| 风险评分 | 评分模型版本、逐项输入、缺失项、计算式、校准区间 | 只显示“风险高” |
| 鉴别/归纳建议 | 已被人工确认的事实及其来源；清楚标记为建议 | LLM 自行创造诊断事实 |

事实时间必须同时展示临床发生时间与系统接收时间，避免时区或延迟造成误解。置信度只能使用 ADR-009 已校准且适用于当前分群的分数，否则显示“不具备校准置信度”。

### 3. 确定性解释渲染

临床文案由结构化证据生成：模板读取 `claim + facts + derivation + source`，不能重新调用知识检索替换来源。模板执行引用完整性检查：

- 每一 `claim` 至少关联一个合格 `source_ref`；
- 数值展示值必须与 `fact_ref` 的规范化值和原单位一致；
- 条件中的“大于/小于/不高于/不适用”等逻辑关系不得被改写；
- 任一关键引用缺失、版本不匹配或时间过期时，解释显示“证据不可完整验证”，不生成完整结论式文案。

指南版权、许可和院内可展示范围需逐项确认，具体来源与片段为 `[待验证]`。验证方法：法务核对许可/引用政策；临床审核团队逐条判断证据是否足以支持声明；系统用字符数和展示许可规则测试截断与替代链接。

### 4. 可读界面与审计

界面提供“结论—为什么—数据—来源—时间”折叠层级；展开不触发临床写入。外部链接仅作导航，必须同时显示院内归档 ID、内容摘要和版本。审计保存解释快照、渲染模板版本和展示时间，避免以后台重渲染改变历史。

临床人员可反馈“证据相关/不相关/过时/冲突”，但反馈不直接改写事实；经治理后产生新规则/模板版本。解释完整率纳入门禁，但任何不完整解释不得被填成看似确定的句子。

## 可复算推导

单条建议的解释完整率：

`evidence_completeness = verified_required_claims / required_claims`

若某建议要求 5 个声明，4 个引用、事实、版本和时间均通过校验：

`4 / 5 = 0.8 = 80%`

它只能显示部分证据，且结论必须按关键声明缺失策略阻断或降级，不能将 80% 表述为“充分解释”。

证据对象增长按月建议量 `A=10,000,000`、平均每条 `E` 个节点估算：

`nodes_per_month = 10,000,000 × E`

若 `E=12`，则为 `120,000,000` 个逻辑证据节点/月。实际对象大小、去重率和写放大需基准测试，`E` 与大小为 `[待验证]`。验证方法是抽取不少于 10 万条经批准的合成/去标识化建议，测每条节点数分布、P50/P95/P99 字节、索引放大和 WORM 写入速率，再按峰值系数保守规划。

解释渲染延迟为：

`t_explain = Σ(t_fetch_i + t_verify_i) + t_render`

每条 12 节点若每次并行验证 6 批、每批 20 ms、渲染 50 ms，则 `⌈12/6⌉ × 20 + 50 = 90 ms`；这只是串行上界算例，缓存命中率、签名验证和冷缓存性能为 `[待验证]`，须在目标硬件测量 P95/P99。

## 安全后果

- 精确引用降低“模型认为”的不可审计性，但也暴露更多指南片段和患者事实，须控制展示与访问。
- 来源许可可能限制原文，平台应提供合法摘要/标识和院内授权链接，而非绕过版权。
- 证据 DAG 增强重放能力，存储与版本管理成本上升。
- 证据不完整时必须诚实降级；不能为提高完整率自动补造“合理依据”。

## 回滚方案

1. 解释渲染模板异常时回滚至上一签名模板，结构化证据 DAG 保持不变。
2. 来源库升级失败时固定上一内容摘要版本，未知来源只显示“无有效引用”。
3. 证据校验过严导致关键展示缺失时启用“仅原始事实与规则 ID”安全视图；不得关闭引用校验。
4. 回滚验收包括所有 claim 可定位、数值/单位一致、时间与版本正确、历史快照可重放和无效引用 100% 被标记。
