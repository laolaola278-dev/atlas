## 背景

真实患者数据能提高负载真实性，却会复制高敏数据到施压机、消息、日志、崩溃转储、监控、报告和第三方工具。匿名化、去标识化或仅保留主键并不必然消除再识别；生产报文、数据库快照和备份也不能被称为“安全测试数据”。本 ADR 采用更严格边界：任何压测、性能基准、混沌注入、CI 流量与演示负载只允许平台生成的纯合成患者和设备数据。真实数据派生集不进入压测环境。

临床回顾性评测确有使用经批准数据的需要，但其用途、访问和风险不同，由 ADR-032 独立治理，不能借评测流程进入压测。

## 选项对比

| 方案 | 真实 PHI 风险 | 可重复性 | 外部工具风险 | 结论 |
|---|---:|---:|---:|---|
| 直接使用生产数据/报文/备份 | 极高 | 中 | 极高 | **严禁** |
| “去标识化”患者数据压测 | 仍可能再识别 | 中 | 高 | **不进入压测** |
| 纯合成手工固定样本 | 极低 | 低 | 低 | 规模与分布不足 |
| 受约束纯合成生成器 | 极低 | 高 | 可控 | **采用** |
| 真实数据只在封闭生产性能观测 | 不属于压测但仍有风险 | 低 | 取决于系统 | 需另立审批，不由本 ADR 授权 |

## 决策

### 1. 绝对边界

1. 压测源只能由 `atlas-loadgen` 合成器生成；每条数据有 `synthetic=true`、生成器版本、随机种子、schema 版本和不可伪造批次签名。
2. 禁止把生产 HL7/FHIR/MQTT 抓包、数据库 dump、对象文件、日志、审计导出、备份恢复数据或故障转储回放为压测负载。
3. 禁止把真实患者名称、证件、电话、地址、住院号、设备序列、就诊文本或从生产提取的稀有组合替换几个字符后用于压测。
4. 去标识化数据即便通过伦理审批，也不进入性能环境；需要临床真实性时只可在受控临床评测流程中使用，不能连接压测工具。
5. 压测环境默认断网、拒绝外部 DNS、使用独立合成身份和一次性凭据；无生产数据库、HIS、EMPI、消息、对象存储凭据。
6. 压测日志、截图、指标标签、JIRA/Git 附件和最终报告只能包含合成引用，禁止上传原始生成语料到公共制品库。

### 2. 合成器设计

| 数据类型 | 生成方法 | 不变量 |
|---|---|---|
| 患者/就诊 | 虚构姓名池、随机内部 ID、虚构院区与科室 | 无真实患者标识；同一场景内可追踪，跨场景不可关联 |
| 检验/生命体征 | 边界值、正常、异常、缺失、乱序、重复和坏质量码 | 数值分布不复制单个真实患者轨迹 |
| HL7/FHIR | 生成器直接构造符合 Profile 的虚构资源 | 官方 validator 通过 |
| 设备流 | 可重复波形、丢包、乱序、断连、时间漂移 | 覆盖容量与故障状态，不复刻个人轨迹 |
| 医保/规则 | 虚构组合与合成知识夹具 | 不从真实患者反推规则覆盖 |
| 攻击样本 | 虚构恶意字符串和合成凭据 | 仅授权环境，不能命中真实服务 |

随机种子决定生成序列，同一版本+种子+参数可复现；生产环境绝不能提供“按患者查询”的隐藏 API 供压测器读取。

### 3. 四道门禁

| 门禁 | 检查 | 失败动作 |
|---|---|---|
| 代码门禁 | 生成器来源、fixture 白名单、无生产连接依赖 | CI 失败 |
| 数据门禁 | 标识符正则、字段字典、熵、来源标记、批次签名 | 拒绝装载并隔离样本 |
| 网络门禁 | egress deny、虚拟私网、服务身份只绑定合成租户 | 中止压测 |
| 运行门禁 | 请求中 `synthetic` 标签、路由/EMPI 租户和审计 | 检测到非合成来源立即 fail-stop |

真实患者数据检测不是单一正则。按附件要求组合正则、字典和熵检测，并增加来源证明；熵只能提示，不能单独确认。规则在中文、多院区、嵌套压缩数据和第三方工具输入上的召回率/误报率为 `[待验证]`。验证方法：由隐私团队建立带标注的合成攻击集和隔离测试集，逐版本测 precision/recall，并在 CI 用合成金丝雀证明检测器自身有效。

### 4. 样本治理

- 生成样本有 7 天自动销毁期限，确需保留的只保留 schema、统计分布和随机种子，不保留可识别生成明细。
- 崩溃附件和 debug dump 走 ADR-025 白名单；原始压测数据存放在合成专用桶，自动过期。
- 报告只写分布、吞吐、延迟、错误率和生成参数；报告附件不附完整患者列表。
- 发现疑似真实数据时立即停止压测、隔离环境与制品、保全审计、启动隐私事件流程；不能用“样本已删除”代替影响评估。

## 可复算推导

### 施压机容量与倍率

附件给出 40 台压测机、每台 50,000 消息/秒：

```text
总施压能力 = 40 × 50,000 = 2,000,000 消息/秒
```

倍率必须明确分母：

```text
相对 1,000,000 点/秒平台目标：
2,000,000 ÷ 1,000,000 = 2 倍

相对 50,000 消息/秒的接入子目标：
2,000,000 ÷ 50,000 = 40 倍
```

因此“40 倍”只对 50,000 消息/秒子目标成立，不是相对 1,000,000 点/秒全平台目标。两个指标口径不同，性能报告不得混用。单台能力、线缆和协议是否可达到 50,000 消息/秒均为 `[待验证]`，验证方法是以纯合成二进制和压缩流量分别校准，统一换算点/秒与消息/秒。

### 生成数据量

1 小时、100,000 点/秒、平均 128 字节/点（大小分布为 `[待验证]` 的演算输入）：

```text
点数 = 100,000 × 3,600 = 360,000,000 点
字节 = 360,000,000 × 128 = 46,080,000,000 字节
      = 46.08 GB（十进制）
```

若平均消息/点为 256 字节，则为 92.16 GB。存储不是所有样本的无限累积，优先在线生成、窗口回收；确需落盘用分段、压缩和 7 天销毁。128/256 字节均为演算参数，验证方法为分资源类型采样 p50/p95/p99 大小并按实际协议重算。

### 合成标签开销

若每点增加 20 字节标签（该开销为 `[待验证]` 的演算输入）：

```text
1,000,000 点/秒 × 20 = 20,000,000 字节/秒
             = 20 MB/秒
1 小时 = 20 × 3,600 = 72,000 MB = 72 GB
```

因此不把长 JSON 标签逐点内联；采用固定批次头、采样确认和路由级租户标记，并在接入端生成紧凑事件 ID。具体格式需在 10% 负载测 CPU/带宽影响。

## 安全后果

- 再识别：即使字段已替换，罕见时间线+病种+院区组合仍可能识别个人，故只使用与真实分布无关的合成轨迹。
- 凭据泄漏：压测系统被入侵可能获得过高生产权限，因此使用无生产权限的一次性身份和网络隔离。
- 假阳性影响交付：检测器误报会阻断合法合成样本，需分类复核但不允许全局忽略高危命中。
- 数据爆炸：生成器也可能造成存储和日志 DoS，采用配额、窗口和 fail-stop。
- 合成模型输出仍可能包含训练记忆中的真实信息；压测若调用模型，只允许固定无患者上下文的合成提示，并扫描输出；模型数据边界仍需验证。
- 性能结论可能被错误数据分布扭曲；报告必须附生成器版本、种子、分布摘要和合成证明。

## 回滚方案

1. 新生成器先以 1% 流量 shadow，校验 schema、分布和检测门禁，再逐步提高。
2. 发现生成偏差时停止目标压测，回退上一签名生成器；不得临时切到生产样本。
3. 检测器误报时隔离该样本并修正字典/规则，检测器保持 fail-closed；禁止通过关闭检测恢复。
4. 若发现疑似真实数据，立即终止施压机和目标环境网络，隔离日志/制品/报告并启动隐私事件响应。
5. 清除合成环境时同时撤销一次性凭据、销毁生成明细和过期备份元数据；保留不含患者内容的审计证据。
6. 恢复压测前重新通过四道门禁，并从较小比例重跑，不得直接恢复原高负载。
