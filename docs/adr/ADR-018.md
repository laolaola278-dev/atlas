## 背景

平台要求每小时生成 10,000 份结构化文书，P95 小于 20 秒，且明确禁止 LLM 自由文本直接进入病历。自由文本会产生字段错位、单位漂移、否定词丢失、无法编码、模板注入和无法机器校验等问题；但完全固定模板又难以覆盖不同科室。决策必须同时约束输出语法、临床语义、术语来源、证据引用与人工签核。

本 ADR 采用“模型只提议结构化片段，Schema 与确定性服务裁决合法性，医师签核后才能形成正式文书”的边界。模型不会直接连接 EMR 写账号。

## 选项对比

| 方案 | 结构可校验 | 表达力 | 主要风险 | 结论 |
|---|---:|---:|---|---|
| 纯自由文本 + 编辑后复制 | 低 | 高 | 漏项、单位错误、提示注入、不可追溯 | 禁止 |
| 单一固定表单填充 | 高 | 低 | 科室差异大，模型优势被浪费 | 仅用于结构化小模板 |
| 自由文本作为 JSON 字符串字段 | 中 | 高 | 校验器无法检查内容与单位，易绕过 | 禁止作为正式结构字段 |
| JSON Schema + FHIR Profile + 术语绑定 + 字段级溯源 | 高 | 高 | Schema/术语治理工作量较大，失败需可解释降级 | **采用** |
| 确定性表单与模型二选一 | 高 | 中 | 不能组合证据选择和结构化表达 | 不采用 |

## 决策

### 1. 四层输出契约

1. **语法层**：模型输出必须符合版本化 JSON Schema；禁止额外字段，关闭可执行内容与 HTML。
2. **语义层**：服务端把症状、部位、程度、否定、时间、趋势等拆为独立字段，不从长句反向猜测。
3. **术语层**：检验、诊断、药物、部位等编码必须来自本院批准且已锁版本的术语集；模型只能返回候选概念，编码映射由确定性服务完成。
4. **证据层**：每个临床断言至少绑定结构化来源；无证据的字段保持空值并要求医师判断，不允许模型补写事实。

JSON Schema 只是结构契约，不等同于临床正确性。通过语法校验不构成签核，也不允许进入正式病历。

### 2. 建议对象的最小结构

| 字段组 | 必要内容 | 校验方式 |
|---|---|---|
| `document_meta` | 文书类型、schema 版本、生成模型与提示模板版本、院区 | 白名单、版本存在性 |
| `patient_context_ref` | 院内患者引用、就诊引用、访问目的 | 作用域校验；日志中不输出明文身份 |
| `assertions[]` | 编码、显示文本、数值+单位、方向、否定、发生/观察时间 | 类型、单位和术语绑定 |
| `negations[]` | 被明确否定的症状/诊断候选 | 非空证据、否定语义检查 |
| `evidence[]` | 来源资源引用、观察时间、值、区间和证据类型 | 必须解析到院内资源 |
| `uncertainty` | 缺失、冲突、置信区间；不输出伪精确概率 | 概率校准规则见 ADR-009 |
| `review_state` | 草稿、待签核、已签核、拒绝、撤回 | 仅状态机可迁移 |
| `provenance` | trace、生成时间、规则/指南版本 | 不可由模型填写 |

### 3. 禁止自由文本直入病历

- 模型生成的自由文本只能出现在隔离的“建议预览”区，必须有明显的非病历标识。
- EMR 写入服务只接受已签核对象、签核人、签核时间、内容哈希和 Schema/术语版本；不提供“自动接受”“默认签核”或失败后重试为正式文书的路径。
- 每个字段可由医师修改，但必须记录原建议、修改后值、操作者、原因和时间；正式文书保留“AI 辅助生成”来源。
- 否定、剂量、过敏、单位、时间紧迫性、手术状态等高风险字段默认需要重点复核；是否需要双人复核由临床治理委员会批准。
- 任何 Schema、术语或模板降级都只能产生“无法生成/待人工录入”，不得部分文本直写。

### 4. 失败与修复

| 失败类型 | 系统行为 | 禁止行为 |
|---|---|---|
| JSON 解析失败 | 隔离原响应，按固定次数进行结构化重试 | 把原文当病历 |
| Schema 不通过 | 返回字段级错误，不回写 | 自动删除未知字段后回写 |
| 术语未绑定 | 保留原词供人工映射，状态为待术语确认 | 猜测编码或从模型记忆选编码 |
| 证据不存在 | 清空相应断言并提示补证 | 生成看似合理的检验值 |
| 置信度未校准 | 不用于自动拦截，只进入普通提示 | 将原始 logits 当临床概率 |
| 生成超时 | 保留已签核内容，不影响既有文书 | 用空内容覆盖病历 |

重试必须有固定上限和总时延预算；原始模型响应只按隐私保留策略保存为加密审计对象，不能写入普通日志。

## 可复算推导

### 文书吞吐与并发（独立于 CDSS 建议负载）

文书硬指标是 `10,000 份/小时`，不能把月均 `10,000,000 次建议` 或 CDSS 峰值 `200 次/秒`直接当作文书到达率。先定义文书专属过程：

```text
λ_doc = 10,000 ÷ 3,600 = 2.778 份/秒
L_doc = λ_doc × W_avg
```

`W_avg` 是文书管线从接收到达 Schema/术语校验完成的平均在制时间，必须从合成负载的完整分布测得；P95 `20s` 不能替代平均 `W_avg`。若仅作保守容量上界，暂时把 `W=20s` 当作上界（不是 Little 定律的均值证明）：

```text
L_bound = 2.778 × 20 = 55.56 份在制
30% 余量槽位 = ceil(55.56 ÷ 0.70) = 80
```

这两个数字只用于初始资源预算，不能证明 80 个槽位或任何实例数满足 P95。文书峰值到达率、突发系数、平均/分位服务时间、模型与规则依赖比例均为 `[待验证]`；压测必须使用独立文书负载模型，分别记录接收、排队、模型、Schema、术语和提交阶段，并验证 `10,000 份/小时` 与 P95 `<20s`。CDSS 的 `13×20=260 次/秒`仅是上游建议容量，不能替代文书容量。

### 存储与版本

每份结构化建议暂按 64 KiB 规划，该大小为 `[待验证]`：

```text
10,000 份/小时 × 64 KiB × 24
= 640,000 KiB/小时 × 24
= 15,000 MiB/天
= 14.6484375 GiB/天（未计副本与索引）
```

版本只追加，不原地覆盖。Schema 新旧版本在迁移窗口内并存，正式对象记录生成时版本和签核时解析版本；这会暂时增加容量。验证方法是从真实结构分布中抽取不少于 10,000 份经批准样本，统计序列化字节 p50/p95/p99，并按峰均比和副本/索引系数重算容量。

## 安全后果

- 提示注入可能诱导模型输出伪造字段；结构校验、证据存在性校验和人工签核共同阻断，但不能保证语义无误。
- 错误单位比语法错误更危险；每个 `Quantity` 必须绑定 UCUM 或院内批准单位，并由规则检查范围，范围仅用于提示，不自动改写。
- 模型可能泄露患者上下文；模型适配器在出库前执行字段策略，推理日志只保留受控引用和哈希。
- 术语版本漂移会导致同一文本含义变化；每次绑定记录概念系统、版本、院区和映射依据。
- 结构正确但临床错误仍可能进入病历；因此保留字段级溯源、修改审计、双人高风险复核和可撤回机制。

## 回滚方案

1. 新旧 Schema、提示模板和模型均不可变版本化；生产开关按院区与文书类型灰度。
2. 发现结构或术语错误时，停止生成新草稿；已签核文书不自动改写，先由临床负责人判定是否发起更正流程。
3. 在 15 分钟内将路由切回上一已验证版本；未完成校验的草稿保持隔离并通知审核者。
4. 终止模型调用后保留术语与证据引用本地解析能力，确保历史草稿仍能渲染和追溯。
5. 导出受影响草稿的 `generation_id`、Schema/模型/术语版本和签核状态，按患者或文书范围进行影响分析。
6. 恢复门禁：连续 1,000 份合成/经批准样本通过 Schema、术语、官方 FHIR 校验器及双人安全用例；回滚期间生成物不得直接成为正式病历。
