# ADR-002：双人复核的适用范围与例外流程

## 背景

Atlas 的建议不得自动进入病历或医嘱；但在抢救、手术室、急诊和设备故障等场景，延迟等待第二审核可能增加患者风险。系统需要把“临床紧急性”与“普通审核便利”明确分开：双人复核是风险控制门槛，抢救破窗是受控例外，事后补签是责任闭环；三者均不能取消患者身份核对、签名、理由记录和全量审计。

## 选项对比

| 方案 | 抢救场景 | 常规安全 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|---|
| A：所有建议一律双人审核 | 严格等待 | 最高一致 | 规则简单 | 可能延误抢救 | 拒绝 |
| B：全部动作单人审核 | 快 | 依赖单人 | 操作简单 | 高风险动作保护不足 | 拒绝 |
| C：风险分级 + 抢救一次性破窗 + 强制事后补签 | 风险自适应 | 高风险双人 | 兼顾安全与救治 | 状态与审计更复杂 | **采用** |

## 决策

### 1. 双人复核适用范围

复核策略由可版本化的确定性规则计算，不允许 LLM 自行决定。满足任一条件即要求两名具备相应执业权限的独立人员审核：

| 风险类别 | 典型触发条件（由规则数据表达） | 审核要求 |
|---|---|---|
| 致命/严重禁忌 | 命中高严重度且证据有效的禁忌规则 | 主审 + 独立复核 |
| 高危药物 | 高警示药物、妊娠/哺乳相关、特殊人群、多药相互作用 | 主审 + 药学或临床复核 |
| 高危治疗 | 化疗、输血、侵入性操作相关建议、抗菌升级 | 主审 + 专科复核 |
| 身份或证据不确定 | 患者身份未达到自动匹配门槛、关键证据缺失/冲突 | 禁止进入复核队列，先解决上游问题 |
| 模型/策略降级 | 规则或模型处于灰度、证据漂移、强制停用恢复期 | 附加独立复核，不自动降级门禁 |

分类规则及具体药物、治疗清单必须由临床治理委员会逐条批准；本规划不把未审清单视为医学事实。清单与临床适配结果为 `[待验证]`。验证方法：对每个触发条件建立正例、负例和边界例，交由至少两名相应专业审核者复核，并在规则发布前做零漏判门禁；任何冲突进入版本变更流程。

两名审核者必须是不同自然人、不同可追责身份，不得共享账号或使用同一终端会话；系统按组织和科室权限限制其可复核范围。第二签核只确认明确列出的建议版本、字段和证据，不可用泛化的“同意”替代逐项审阅。

### 2. 抢救破窗状态机

破窗不是永久权限，也不是绕过数据库约束。它使用独立的 `EmergencyActionGrant`，绑定单一患者、单一建议版本、单一执行动作、理由、授权人、有效期、策略版本和一次性 nonce；该 grant 不能转换为普通 `ApprovalProof`，不能进入普通 `APPROVED`/`COMMITTED` 写回路径。数据库对紧急意图使用独立表、唯一 nonce 和追加审计约束，目标数据库行为仍需 `[待验证]` 集成测试。

```text
PENDING_REVIEW
  ├─ 正常双人审核 → APPROVED → COMMITTED
  ├─ 普通拒绝/撤销 → REJECTED / REVOKED
  └─ 临床紧急 → BREAK_GLASS_AUTHORIZED
                    → EMERGENCY_PENDING_CONFIRMATION
                    → EMERGENCY_RECORDED / EMERGENCY_UNKNOWN
                    → POST_REVIEW_REQUIRED
                    → RECONCILIATION_CONFIRMED / CORRECTION_REQUIRED
                    → ARCHIVED
```

抢救分支不得直接进入普通 `COMMITTED`；紧急动作是否执行必须由目标回执或对账确认，事后复核只确认/更正已发生的紧急事实，不能借补签再次执行普通建议。

启用破窗必须同时提供结构化理由码、自由文本说明、预计行动、替代方案不可用说明、在场人员与设备/电话标识，并由有抢救权限的临床人员签核。默认凭证只对当前动作有效、短时有效且不可批量使用；具体时限由临床治理委员会确定，不在本 ADR 虚构医学标准。时限与跨设备应急流程为 `[待验证]`。验证方法是开展高保真抢救演练，分别测试网络中断、认证服务不可用和跨工作站接续，测量从破窗请求到执行的 P99/P999，并由临床安全委员会批准上限。

### 3. 事后补签

抢救执行后，系统立即创建 `BREAK_GLASS_RECONCILIATION_REQUIRED` 事件和不可跳过任务。第二名独立审核者必须核对实际执行事实、患者、动作、剂量/内容、执行时间、原始理由和执行者；审核结果只能是：

- `CONFIRMED`：事实与紧急签核一致，第二签确认；
- `AMENDMENT_REQUIRED`：需追加更正或受控冲正，不能把原动作伪装成正常审批；
- `ESCALATE`：存在身份错误、越权、重大偏差或无法确认，立即转医疗安全事件。

补签不得把时间回填到原事件，也不得改写原证明；所有追加事件带服务器时间和 `based_on_event_id`。到期未补签触发升级通知、值班负责人处置和监管/合规导出，但不阻塞已经发生的临床救治。

默认提醒、升级和最长补签窗口需按医院制度确定，候选值为 15 分钟首次提醒、30 分钟值班升级、60 分钟未闭环进入安全事件。该候选值未作临床验证，标为 `[待验证]`。验证方法：对不少于 30 次桌面演练测量补签可用性，审查漏升级场景并由医疗质量、信息安全和伦理/法务共同批准。

### 4. 全量审计

每个破窗至少产生以下不可变事实：请求者、批准者、在场人员、患者、建议及版本、目标动作、理由、替代方案、时间、设备/网络状态、证书、实际执行、第二审核、每个通知、异常和最终处置。日志必须记录失败尝试和被拒绝的第二签核。

| 审计对象 | 必备字段 |
|---|---|
| 破窗请求 | who/when/what/why、临床紧迫码、患者风险上下文、策略版本 |
| 签发与消费 | 证书标识、签名密钥标识、`nonce`、一次性消费结果 |
| 实际执行 | 执行者、设备、执行回执、时间、失败/重试关系 |
| 事后补签 | 第二审核者、决定、差异、冲正/升级引用 |

## 可复算推导

双人复核要求可由“每条建议风险分值”计算：

`required_reviews = 1 + I(high_risk) + I(evidence_uncertain)`

其中 `I` 为指示函数，证据不确定时系统直接阻断而不是增加审核人掩盖不确定性。`high_risk=0` 时需 1 人；`high_risk=1` 且证据确定时需 2 人。破窗覆盖量可用：

`unsigned_queue_after = max(0, unsigned_queue - confirmed_break_glass - rejected_or_expired)`

例如峰值待审 5,000 条、其中 20 条为受控破窗，验收不增加漏审量：`5,000 - 20 = 4,980` 条仍需正常队列处理。该数值是算例，不替代附件的审核台 5,000 并发压测目标。

## 安全后果

- 正面：把紧急例外限制到单一患者、单一动作、一次性、短时和事后独立复核；可量化紧急通道使用率。
- 负面：紧急模式可能被滥用，认证服务故障可能影响救治；因此提供院内受控离线核验材料，但不得预置长期万能令牌。
- 警报：破窗率、同一人员连续破窗、理由缺失、事后未补签、跨患者重放均为安全信号。
- 临床边界：系统只支持临床人员执行和记录，不决定抢救指征，也不自动开立医嘱。

## 回滚方案

1. 规则发布失败时，固定到最近一个已签核规则集；不得降级为全部单人审核。
2. 破窗服务异常时切换到医院批准的人工应急登记本/受控离线流程，恢复后以唯一事件号补录并对账；所有未补录动作进入安全升级。
3. 若双人队列造成非紧急延迟，可调整通知与排班，但不能改变该建议的强制复核级数。
4. 回滚演练至少覆盖数据库、认证、消息总线和时钟漂移故障；任何未闭环破窗逐条列出责任人与处置。
