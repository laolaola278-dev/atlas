## 背景

附件要求三级及以上系统处理核心数据强制使用 SM2/SM3/SM4，并要求智能体实例与物理服务器 MAC 绑定防非法迁移；同时要求国密签名、WORM 审计和密评材料随代码交付。国密落地不能只在 HTTPS 配置中勾选算法名称，必须贯通密钥生成、身份认证、传输协商、字段加密、完整性校验、签名、备份、轮换、吊销、销毁与第三方验证。

本文采用国家标准和经认证产品的参数，但附件中的标准状态、适用范围、算法模式、证书策略及“强制”边界均须由合规负责人验证。凡未取得标准原文、产品认证报告和密评机构书面意见的内容均标 `[待验证]`。

## 选项对比

### 密码实现与部署

| 方案 | 密钥保护 | 性能/运维 | 合规证据 | 结论 |
|---|---|---|---|---|
| 应用内纯软件国密库，密钥在环境变量/配置文件 | 弱，易泄露 | 初始简单，主机失陷即失守 | 难证明 | 禁止用于生产根密钥 |
| 通用 HSM/加密机 + 应用密码适配层 | 强 | 需容量与网络设计 | 可形成密钥与算法证据 | **采用** |
| 每服务独立软件密钥 | 隔离较好 | 轮换复杂、易漂移 | 证据碎片化 | 仅用于短期数据密钥且须受 HSM 保护 |
| 完全依赖外部密码云 | 取决于跨域与出网 | 违背数据不出院时不可用 | 责任边界复杂 | 核心数据不采用 |

### 数据保护方式

| 方案 | 保护范围 | 代价 | 结论 |
|---|---|---|---|
| 仅传输加密 | 网络链路 | 落盘明文、备份和导出失守 | 不足 |
| 透明数据库整库加密 | 存储介质 | 应用层仍拿明文，字段级授权弱 | 作为基础层采用 |
| 字段级信封加密 | 敏感字段、密钥、令牌 | 密钥与查询设计复杂 | **核心敏感字段采用** |
| 客户端持有长期数据密钥 | 降低服务端风险 | 终端丢失影响大 | 医疗工作站场景优先硬件/短期凭据 |

## 决策

### 1. 算法职责

| 目的 | 采用算法 | 强制规则 |
|---|---|---|
| 身份认证、密钥协商、非对称签名 | SM2 | 私钥不可导出；SM2 证书绑定主体、用途和有效期 |
| 完整性、摘要、审计链、制品摘要 | SM3 | 摘要必须绑定规范化内容、版本与域分离标签 |
| 数据加密 | SM4 | 使用经确认的认证加密模式或“SM4 密文 + SM3 完整性”的获批组合；具体模式不得自行假定 |
| 密钥随机数与填充 | 采用对应标准或认证产品规定 | 不得复用 nonce/IV，不以固定值“提高兼容性” |

SM2 不用于对称批量加密，SM3 不替代签名，SM4 也不单独承担认证与完整性保护。算法名称、模式、编码、参数长度以标准原文、模块手册和互操作测试结果为准。

### 2. 传输

1. 院内互信边界通过国密安全网关建立受认证通道；报文包含协议版本、证书链、随机数、时间窗口和密文上下文，防止跨协议重放。
2. 服务身份优先使用经院内 CA 签发的 SM2 证书，双向认证；不得以共享静态口令代替服务身份。
3. SM2 身份认证与 SM4 数据密钥协商的密码协议需选定为标准或认证产品支持的具体方案。普通 TLS 1.2/1.3 不当然等同于国密通道，兼容性均为 `[待验证]`。验证方法是对目标网关/客户端执行标准握手向量、证书链、错误握手、截断重放和跨版本测试，并以第三方检测报告确认。
4. 外部模型或服务只接收去标识聚合字段；禁止先解密再在通用代理中转发原始 PHI。混合协议边界必须有显式数据出口策略。

### 3. 存储

- 基础设施层：数据库页、备份、对象存储和日志卷使用硬件支持的整盘/卷加密；密钥由 HSM 包装，不与密文同域保存。
- 应用层：患者标识、证件、精确时间线、原始病理、模型提示上下文等高敏字段采用信封加密。每个对象有明文格式版本、算法、密文格式、nonce、认证标签、密钥版本和 AAD 绑定。
- 查询索引只保存盲索引或受控伪名；盲索引 HMAC 密钥与数据密钥分离，并支持合规轮换后的双密钥验证。
- WORM 审计保存 SM3 链摘要、SM2 签名和签名证书；第三方只读校验接口可用相同算法重算，不持有生产私钥。

SM3 摘要与 SM2 签名不能相互替代；删除/归档策略必须与审计保留义务一致。

### 4. 签名与审计

1. 每个签核或审计事件先按规范序列化并计算包含域标签的 SM3 摘要。
2. 为避免 20 亿条/天逐条在线签名造成不可接受的集中瓶颈，按时间和站点构造 Merkle 批次；例如每秒一个根、每秒一个 SM2 签名，批内每个事件仍可独立重算。
3. 批次签名覆盖根哈希、前一批根、站点、批次起止时间、序列和算法标识，形成防重排链。
4. 单个事件的不可否认性由“事件摘要 + 包含它的已签名批次根”共同提供。第三方接口返回验证结论、失败字段和证书状态。
5. 签名失败时受保护事务不得确认成功；若仅审计归档失败，按 ADR-019 的受控待确认路径处理。

### 5. 密钥托管与生命周期

| 阶段 | 控制 |
|---|---|
| 生成 | 在 HSM 内生成，权限分离；备份密钥材料须按设备规范导出并离线加密 |
| 分发 | 数据密钥经包封密钥传递；应用只获得使用权限，不获得明文根私钥 |
| 使用 | 审计服务账号、用途、院区和调用次数；默认禁止导出 |
| 轮换 | 根密钥、签名密钥、数据密钥分级轮换；密文保留旧版本解密能力，盲索引支持双版本 |
| 吊销 | 证书吊销、服务隔离、强制轮换、影响面审计 |
| 备份 | 至少两处独立保管的恢复材料与使用审批；不得与应用镜像同包 |
| 销毁 | 到期且无保留义务后执行可证明销毁，同时保留非敏感销毁证明 |
| 应急 | 吊销泄露密钥，验证旧密文影响，按事件响应流程处置 |

密钥管理服务、HSM 型号、算法模式、轮换周期和 MAC 绑定实现均需在选型后标 `[待验证]`。验证方法包括密钥注入/导出拒绝测试、备份恢复、性能基准、产品认证证书核验以及密评机构预审。

## 可复算推导

### 审计签名吞吐

```text
20 亿条/天 ÷ 86,400 秒/天
= 23,148.15 条/秒（平均）

每秒一批：
= 86,400 批/天
= 20 亿事件 ÷ 86,400 批 = 23,148 事件/批（不是批数）
```

若为满足 60 秒切换还需预热密钥，缓存不参与正确性。批大小是平均值，不代表突发；生产必须按 30% 余量设计并实测。

### 加密膨胀

设每条密文使用 nonce 长度 `N` 字节、认证标签长度 `T` 字节，原始明文 `P` 字节：

```text
密文有效载荷 C = P + N + T（不计传输封装）
膨胀率 = (N + T) ÷ P
1 MiB 明文、假定 N=12、T=16 的示例：
  额外字节 = 28
  膨胀率 = 28 ÷ 1,048,576 = 0.00267%
```

`N=12、T=16` 仅为演算假设，不能据此选择生产模式。验证方法是对最终模式读取参数说明，使用 1 KiB、1 MiB、64 MiB 三档明文测得 C/P，再以最大消息和最高点速率压测 CPU、内存、带宽与尾延迟。

### 密钥容量

若在线签名采用每秒一批：

```text
每秒 1 个 SM2 签名 = 3,600 个/小时
24 小时运行 = 86,400 个签名/天
```

这不表示根私钥可批量“签出”私钥；根密钥始终在 HSM 私钥边界内，只执行签名操作。

## 安全后果

- 软件密钥失陷会导致全局失守；HSM 降低风险但增加故障域和单点依赖，须做双机/跨站点高可用与手工降级预案。
- 国密通道错误降级到非国密通道会破坏合规边界；策略必须默认拒绝弱算法，而非自动兼容。
- nonce 重复、密钥版本丢失、AAD 未绑定、证书用途错误会破坏机密性或完整性；属性测试和篡改测试必须覆盖。
- MAC 绑定若只检查启动时 MAC，运行中热迁移可能绕过；应结合可信启动、设备身份证明和写入 fencing。绑定方案的抗迁移能力为 `[待验证]`，验证方法为在授权迁移、非法迁移、网络断开和虚拟机克隆场景下做负向测试。
- 加密提高取证与排障难度；必须提供受审计的最小解密能力，不能让所有工程师默认持有密钥。
- 第三方合规适用性不能由本 ADR 代替；标准效力、等级保护范围、密评方案和产品型号需书面核验。

## 回滚方案

1. 国密能力按传输、存储、签名三个独立开关灰度；每次只启用一个边界，并保留旧适配器但禁止向未批准链路降级。
2. 若新网关握手失败，停止新会话而不是自动改用弱套件；切回上一兼容版本入口，保留失败握手计数和证书链。
3. 若字段加密性能不达标，优先关闭非关键派生索引或扩容 HSM，不允许把明文字段回写生产；必须回滚时先用旧密钥解密受控迁移，再切回上一获批密钥版本。
4. 签名批次故障可缩短批次或提升签名可用性，但不得删除失败批次；回滚后从最后连续链根重算并对账。
5. 密钥轮换回滚不得恢复已泄露私钥；只能暂停轮换、吊销问题密钥、启用备用签名服务，并从最后可信链根继续。
6. 回滚验收包括：证书链验证、篡改检测、跨版本解密、审计第三方校验、密钥导出拒绝和性能预算全部通过。
