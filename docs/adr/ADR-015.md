# ADR-015：数据不出院的本地推理与云端切分

## 背景

附件要求原始诊疗数据 100% 院内闭环，云端仅可接收脱敏聚合指标。医疗文本、检验、用药、影像元数据及其组合即使删除姓名也可能重识别；向量、提示词缓存和错误日志同样属于数据流。模型下载与患者数据上传是两个方向，必须在架构上分离：签名模型可进入医院，原始患者数据不得借模型更新、遥测或远程运维离开医院。

## 选项对比

| 方案 | 患者数据边界 | 私有化质量 | 运维 | 结论 |
|---|---|---|---|---|
| A：直接把临床上下文发云模型 | 易越界 | 差 | 方便 | 拒绝 |
| B：完全离线，连聚合指标也不上传 | 边界最小 | 私有化好 | 集中运营受限 | 安全基线但保留批准遥测 |
| C：临床推理全本地，唯一院内出站代理仅放行已批准脱敏聚合 | 可审计可运营 | 私有化好 | 可控 | **采用** |

## 决策

### 1. 信任域与切分点

定义三个域：

| 域 | 内容 | 网络 | 允许方向 |
|---|---|---|---|
| 临床域 | 患者数据、推理、规则、EMPI、FHIR、审计、WORM | 院内隔离区 | 内部受控调用 |
| 模型管理域 | 签名模型、配置、评测包、召回/停用指令 | 管理区 | 模型入站；不携患者标识 |
| 外部运营域 | 软件遥测、版本/容量统计、ADR-012 批准的聚合 | 唯一出站代理 | 仅 allowlist 聚合出站 |

所有临床数据流终止于院内 `privacy-egress-proxy`。代理与外部通道采用双向 TLS/国密传输方案，具体套件在 ADR-020 决定；数据库账号、应用策略和网络 ACL 三层均默认拒绝。模型权重可入站，但患者数据不可作为推理 API 请求、反馈样本、向量或遥测属性。

### 2. 永不出院字段

以下字段及其可逆派生值禁止离开临床域：

| 类别 | 永不出院字段 |
|---|---|
| 身份 | 姓名、曾用名、证件、联系方式、详细地址、EMPI 原值、住院/门诊原号 |
| 临床事实 | 诊断原文/编码、检验值、用药、医嘱、护理记录、病程、过敏、手术 |
| 影像 | DICOM 实例/像素/元数据、报告原文、影像 URL、截图/OCR 临时数据 |
| 文本 | 病历、报告、病理、自由文本、提示词、患者问答、模型输入输出 |
| 精细时间/地理 | 精确就诊时间、床位、机构、医生、地理轨迹、设备标识 |
| 审计/安全 | 访问事件、同意、策略、模型/规则密钥、患者相关 trace 内容 |
| 衍生高风险数据 | embedding、向量、摘要、裁剪图片、特征、会话缓存、失败请求体 |

只有“无法关联到患者或单一一小群体的批准聚合统计”可出站，例如按服务版本汇总的调用次数、耗时分布分桶和容量水位；小样本单元格需满足 ADR-012 策略并做贡献限制。是否满足不可由数值本身自证，需风险评估。

### 3. 出站数据合同

每种遥测类型有 schema version、字段 allowlist、目的、接收方、保留期、聚合方法、k/抑制规则、合法依据和责任人。代理执行：

1. 消费者身份和服务合同；
2. 目的地 allowlist；
3. 字段级 allowlist；
4. 患者标识、直接/间接标识与高熵值扫描；
5. ADR-012 风险标签、抑制和小样本贡献限制；
6. 速率/体积配额；
7. 加密、签名、审计；
8. 合规版本与策略有效期。

禁止用“模型诊断”分类替代原字段扫描；日志只记录事件元数据和摘要，不落请求正文。遥测失败不影响急诊核心链路，但 PHI 命中立即阻断并产生安全事件。

### 4. 本地推理与模型分发

模型容器/权重、规则、术语和依赖以签名制品从模型管理域进入，在院内验证摘要、证书、SBOM 和评测状态后解包。运行身份最小权限，挂载临床数据为只读（输出仍需写回受控存储），禁用默认公网出口。更新遵循 ADR-016 的影子/灰度/回滚。

云端可接收聚合故障码，但不含自由文本错误消息；诊断包按工单逐字段审批、临时加密授权、到期销毁并全量审计。供应商支持“零数据保留”声明也不能替代网络与代码门禁。

### 5. 网络与验证

院内服务只允许访问院内白名单；DNS、代理、容器运行时和管理面同样限制。CI 用真实患者检测脚本；预生产只用合成数据。网络层捕获测试应证明临床端口无外联。部署地域、云服务处理者和出域/跨境适用性为 `[待验证]`。验证方法：逐服务/容器列出目的地，数据流访谈，法律/合同评估；使用合成 PHI canary 扫描网络、代理、DNS 和日志，任何命中即失败。

## 可复算推导

出站事件率按每个临床请求假设最多产生 `T` 条遥测，日请求 `R`：

`telemetry_per_day = R × T`

若 `R=10,000,000、T=1`，则 `10,000,000/86,400≈115.74 条/秒`；真实 R/T 分布为 `[待验证]`。验证方法：在院内影子部署统计每建议的遥测条数、字段数、字节数和失败重试，按 P99 与日峰值规划。

“永不出院”验收计数：

`patient_egress_violations / tested_patient_fields = 0 / N = 0`

若测试 1,000 万个合成 PHI 字段变体，正确结果必须是零容忍，不能将成功率四舍五入成 100% 而忽略一次泄漏。样本覆盖和攻击工具效果为 `[待验证]`，验证方法：自动扫描 + 人工流量审查 + 抓包 + 越权配置测试，并以零容忍为门禁。

聚合小单元处理前，若事件贡献为 `c`、上限为 `K`，超限单元可用合并/抑制：

`released_count = Σ I(group_count ≥ K) × group_count`

禁止通过反复请求旋转身份规避单元阈值；代理需维护隐私预算/贡献键。具体 k、隐私预算和服务目的为 `[待验证]`，由风险评审与攻击测试确定。

## 安全后果

- 本地推理保护患者数据，但模型漏洞暴露面位于院内；需要签名、隔离、扫描、最小挂载和持续更新。
- 永不出院清单会约束产品遥测和排障方式，采用聚合/工单诊断降低可观测性，需提前设计。
- 日志、缓存和模型更新通道是常见旁路，网络与运行时双重控制。
- 聚合指标也可能再识别，不能因字段少就默认可出站。

## 回滚方案

1. 出站代理异常时默认关闭外部遥测，院内核心推理继续；聚合事件进入耐久本地队列并限制容量。
2. 发现患者字段出站时立即断开通道、吊销凭据、保全请求/配置、评估影响并启动安全事件；不得仅删除日志后重开。
3. 模型制品异常时回滚至上一签名版本，卸载候选制品；临床推理按 ADR-016 切换。
4. 回滚验收包括临床域零外联、allowlist 生效、队列不丢 PHI、日志无正文、模型可本地启动和旧版本签名有效。
