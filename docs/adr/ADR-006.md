# ADR-006：DICOM 大对象存储、元数据分离与 LLM 边界

## 背景

影像像素体积大、访问模式与业务检索不同；将 DICOM 二进制放入业务数据库会增加备份、检索和扩容耦合。与此同时，影像元数据可用于患者关联、检查导航和报告引用，但未经专门验证的像素或整幅图像进入通用 LLM 会扩大 PHI 暴露、幻觉和不可解释风险。Atlas 自身只消费结构化元数据与经授权的结构化报告。

## 选项对比

| 方案 | 大对象存储 | 检索性能 | LLM PHI 边界 | 结论 |
|---|---|---|---|---|
| A：DICOM BLOB 全部存业务库 | 简单 | 大对象 I/O 拖累事务 | 可额外禁止 | 拒绝 |
| B：全部委托外部 PACS，Atlas 不保存 | 边界清楚 | 受 PACS 约束 | 清楚 | 备份与离线访问不足 |
| C：对象存储保存原始实例；索引库保存检索元数据；FHIR 保存临床引用 | 分层 | 元数据快、像素按需取 | **LLM 无像素通道** | **采用** |

## 决策

### 1. 存储分层

| 数据 | 权威存储 | Atlas 组件 | 保护措施 |
|---|---|---|---|
| DICOM Part 10 原始实例/对象 | MinIO 对象存储（受支持 DICOMweb 接口） | `atlas-ingest-dicom` | 加密、对象版本、不可变保留策略、哈希清单 |
| 患者/检查/序列/实例索引 | 业务分片库 | 影像元数据索引 | 命名空间、EMPI 外键、事务 outbox |
| FHIR `ImagingStudy`/`DiagnosticReport` | FHIR 服务 | 医生工作站 | Profile、术语、审计 |
| 报告文本 | 文档/对象存储 + FHIR 引用 | `atlas-record`/审核台 | PHI 最小化、版本和签名 |
| 像素派生特征 | 独立、经注册验证的影像算法域 | 不进入 Atlas LLM | 单独产品/模型注册与人工复核 |

对象键不得包含姓名、证件号等直接标识符，使用不可逆内部标识加随机/内容摘要命名。元数据索引保存 SOP Instance UID、Study/Series UID、模态、尺寸、切片位置等互操作字段以及来源对象版本；临床显示所需姓名映射在受控视图解析。

### 2. 完整性与写入顺序

采用“暂存对象→恶意/格式检查→内容哈希→元数据校验→原子发布”流程：

1. 接收原始字节并流式计算 SHA-256；计算算法和实现需要按密码合规基线确认。目标国密摘要的具体使用为 `[待验证]`，由密评/密码应用方案确定 SM3 与标准摘要的并存策略。
2. 检查 DICOM 语法、传输语法、大小上限和允许标签；解析失败对象保留在隔离区，不进入临床索引。
3. 在对象存储临时键写入并复制到不可变正式键。
4. 数据库事务写入元数据、来源指针、内容摘要和 outbox。
5. 定期对账数据库引用与对象清单；缺失、摘要不符或未引用对象进入隔离，不静默补写临床数据。

多副本、纠删码及跨可用区布局是部署参数，未在当前附件给出。`[待验证]`。验证方法：在目标硬件和故障模型上执行节点、磁盘、可用区故障测试，测量 RPO/RTO、修复流量、恢复空间和元数据查询 P99。

### 3. LLM 硬边界

- Atlas 推理网关维护允许字段白名单；DICOM pixel data、整幅图像、未经 DICOM 去标识化流程的 OCR/截图以及可重建像素的 token 一律拒绝。
- LLM 仅可接收结构化报告内容、检查元数据白名单和经人工签核的临床事实建议；不接收对象存储 URL、预签名 URL或可逆编码。
- 如果未来需要影像算法，只允许通过独立注册、验证和人工签核的模型服务提供结构化测量/标记；Atlas 不把该算法包装成通用 LLM 能力。
- 日志、向量库、提示词缓存和第三方遥测继承同样禁限；调用前执行 DICOM 标签、URL、base64 长度、MIME、熵和上下文模式检测。
- 脱敏不能仅依赖删除 DICOM 私有标签或烧录文字区域检测失败路径；未经隐私负责人签核的对象不得进入允许出院的边界。

实际 PACS 是否支持选定 DICOMweb 事务与检索能力、烧录 PHI 检测工具的覆盖率为 `[待验证]`。验证方法是逐院区执行 DICOM C/DICOMweb 契约测试，并使用经批准含烧录文字的测试集测量漏检率；任何漏检用例均阻断上线。

### 4. 访问与生命周期

元数据检索按患者、机构、用途授权；像素调阅单独授权并记录 who/when/what/why。对象生命周期使用规则化保留，不允许普通账号覆盖或删除法定保留对象；纠错创建新对象版本。导出按 ADR-012/013 做去标识和最小必要判定。

## 可复算推导

设每年对象数为 `Y`，平均实例大小 `S` 字节，保留 `R` 年，副本/纠删开销系数 `k`（有效容量占原始数据比例的倒数），则原始逻辑容量为：

`V_raw = Y × S × R`

例如 `Y=1,000,000`、`S=20 MB`、`R=5` 年：

`1,000,000 × 20 MB × 5 = 100,000,000 MB = 100 TB`（十进制容量）。

若有效容量系数为 2.5，则物理规划量为：

`V_physical = 100 TB × 2.5 = 250 TB`

并需另加增长、索引、隔离和恢复余量。`Y/S/k` 均未由附件提供且为 `[待验证]`。验证方法是从 PACS 盘点按年度新增实例数、实例大小直方图和对象增长曲线，副本测试测得实际开销后重算；容量误差超过 20% 需重新评审。

## 安全后果

- LLM 无像素通道降低 PHI 和幻觉面，但结构化报告仍可能含敏感信息，须最小化和审计。
- 分离存储提高性能与可扩展性，也引入对象/数据库双写一致性问题；对账与 outbox 是必要控制。
- 对象不可变提高取证能力，但纠错和法定保留需清晰生命周期。
- 影像算法未来接入必须重新进行安全、临床和注册评审，本 ADR 不预先批准。

## 回滚方案

1. 新对象存储适配器异常时停止新发布，保留数据库中 `PENDING_OBJECT` 状态；不得将对象塞回业务库。
2. 客户端不兼容 DICOMweb 时回滚至上一兼容端点或经医院批准的 PACS 只读回源，不更改对象内容。
3. LLM 边界误配时立即撤销相关字段白名单、清理缓存和向量索引，并审计所有调用；无法确认无 PHI 流出时启动安全事件。
4. 恢复后执行对象-元数据全量摘要对账、越权扫描、报告链抽查和 DICOMweb 契约回归。
