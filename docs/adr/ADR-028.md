## 背景

Atlas 同时运行固定基础设施、10,000,000 次/月 AI 建议、高吞吐设备流、20 亿条/天审计和长稳评测。只看云主机总账单无法判断哪个院区、流程或模型优化产生收益；按人数平均分摊又会把急诊和批处理混在一起。另一方面，把患者、诊断或提示词放入计费标签会扩大敏感数据副本。

本 ADR 以“资源可计量、业务事件可归因、财务总额可对账”为目标。成本用于容量规划和透明分摊，不作为减少签核、告警、安全控制的理由。

## 选项对比

| 方案 | 归因精度 | 数据风险 | 运维复杂度 | 结论 |
|---|---:|---:|---:|---|
| 只按云资源项目总账 | 低 | 低 | 低 | 作为财务总账，不用于业务分摊 |
| 集群/节点标签按人数分摊 | 中低 | 低 | 低 | 辅助基线 |
| API 网关按请求估算 | 中 | 低 | 中 | 遗漏后台与存储 |
| 事件账本 + 资源计量 + 月度对账 | 高 | 中低 | 中高 | **采用** |
| 在标签中记录患者/诊断/原始提示 | 高 | 极高 | 中 | 禁止 |

## 决策

### 1. 成本对象与维度

统一使用低基数维度：

| 维度 | 示例 | 约束 |
|---|---|---|
| 组织 | 集团、院区、科室/成本中心 | 仅使用已授权财务编码 |
| 产品能力 | 急诊、病历、CDSS、审计、评测 | 来自服务与工作负载声明 |
| 工作负载 | 实时告警、交互签核、批处理 | 防止高/低优先混算 |
| 模型 | 模型版本、推理模式、上下文等级 | 不记录提示正文 |
| 资源 | vCPU、内存、GPU 秒、对象 GB、消息、出口流量 | 来自云/硬件计量 |
| 时间 | 小时、日、月、账期 | UTC 存储，按院区财务时区汇总 |
| 成本中心 | 临床、行政、研发、平台 | 需财务主数据映射 |

患者、医生姓名、病种、原始提示、自由文本和精确事件时间不作为计费标签。业务关联使用内部事件 ID，在受控账本中一对一映射。

### 2. 计量与分摊顺序

1. **资源真值**：从虚拟化、存储、消息、模型服务、备份和观测平台读取原始用量；资源 ID 映射到院区与集群。
2. **事件分摊**：服务在入口和完成点记录 `billable_event_id`、能力、优先级、模型版本、token/上下文指标或 GPU 毫秒、结果状态。
3. **共享成本**：无法直接归属的集群控制面按“直接用量占比 + 批准权重”分摊。
4. **月结对账**：事件账本分摊之和与资源总账允许存在舍入差，但必须在阈值内解释；原始资源账为最终财务真值。
5. **异常保护**：急诊和签核事件即使成本高也不降低安全等级；预算告警优先扩容、排队或暂停非紧急任务，不关闭告警或签核。

每个事件只计一次；重试按实际资源消耗计入工程诊断，但业务分摊默认归并到原事件并单独展示重试成本，避免把故障转嫁到临床科室。

### 3. 账本与对账

| 账本 | 内容 | 校验 |
|---|---|---|
| 资源账 | 供应商/硬件原始计量、单价版本 | 不可由应用改写 |
| 分配账 | 资源成本按维度分摊 | 总和守恒 |
| 事件账 | 每次业务计算、模型和存储用量 | 幂等、引用 WORM 审计 |
| 预算账 | 预测、承诺、实际、偏差 | 按账期冻结版本 |

价格表带生效区间和币种；历史账单使用当时价格快照，不能用当前单价覆盖。研发、评测和压测成本独立成本中心，压测只能使用 ADR-031 的纯合成数据。

### 4. 治理与展示

- 仪表板同时显示吞吐、单位成功建议成本、单位签核延迟、审计写入成本和急诊可用性，禁止只优化单价而隐藏安全指标。
- 任何预算动作影响临床路径时走变更评审和影响评估。
- 成本优化建议必须附患者安全、合规、正确性、观测和性能影响；优先级仍为患者安全 > 合规 > 正确性 > 可观测性 > 性能 > 代码量。
- 高基数性能标签设置上限；超过阈值只记录聚合计数和采样哈希。

## 可复算推导

### 业务到达率

月均 10,000,000 次建议：

```text
30 天秒数 = 30 × 24 × 3,600 = 2,592,000 秒
平均率 λ = 10,000,000 ÷ 2,592,000 = 3.858 次/秒
峰值系数 = 200 ÷ 3.858 = 51.84
```

成本模型必须既支持平均 3.858，也支持峰值 200；只用均值会把 GPU 与队列峰值漏算。

### 月度模型成本通式

设本地推理占比 `p_l`、单价 `c_l`，院区受控加速/外部调用占比 `p_e`、单价 `c_e`，并加固定资源 `F`、存储 `S`、观测 `O`、备份 `B`：

```text
月模型成本 = 10,000,000 × (p_l×c_l + p_e×c_e)
月总成本 = 模型成本 + F + S + O + B
单位建议边际成本 = 模型成本 ÷ 10,000,000
```

若全部本地且每请求资源成本 `c`：

```text
单位成本 = c
月模型成本 = 10,000,000 × c
若 c=0.01 元/请求，则月成本 = 100,000 元
```

`c=0.01` 仅为演算值，标为 `[待验证]`。验证方法是在目标硬件上运行固定请求分布，分别测 token、GPU 秒、CPU 秒、内存和排队，取完整成本而非仅 API 价格；再与当月资源账和发票/内部折旧表对账。

### 重试成本

```text
有效业务事件成本 C_business
工程总成本 C_total
重试放大率 A = C_total ÷ C_business
A - 1 = 额外故障成本比例
```

若 5% 事件平均重试一次，额外请求为 `10,000,000×5%=500,000`；若每个重试成本与原请求相同，则该部分总请求至少为 1,050 万，而业务分摊仍是 1,000 万。5% 是样例，实际重试率按事件账统计；验证方法是注入超时、连接断开和模型限流，区分“未执行”和“已执行但回执丢失”。

### 分摊守恒

若某月可分摊资源总成本 `T`：

```text
Σ 各成本中心分摊金额 - T = 对账差额
允许舍入 = 维度数量 × 最小货币单位 × 0.5
其他未解释差额必须阻断结账
```

币种最小单位为 0.01 元时，100 个成本中心允许纯舍入最多 0.50 元；实际阈值需结合财务精度，标为 `[待验证]`。

## 安全后果

- 计费标签会复制数据到多个系统，字段白名单和租户隔离必须先于成本展示。
- 错误归因可能导致某科室被收取不合理费用；保留原始事件、映射版本和申诉/更正流程。
- 为降成本缓存更多患者上下文会增加隐私风险；模型上下文最小化和 ADR-015 数据不出院优先。
- 统一价格快照与财务记录很重要；篡改成本账可能掩盖异常调用或数据外流，应接入只追加审计。
- 预算停用不得关闭危急告警、签核或审计；仅能暂停非紧急生成并保留安全余量。
- 模型供应商价格或条款可能变化，历史账单不能随当前页面重算；数据跨境与许可需另行核验。

## 回滚方案

1. 新计量 SDK 先影子计费，不影响财务结算；对照旧系统至少一个完整账期。
2. 发现事件漏记时从资源账按批准权重补分摊，并保留“估算”标记，不能伪造精确事件。
3. 发现重复计费时冻结相关账期、撤回未批准报表并按原 `billable_event_id` 幂等重算。
4. 新成本维度若导致高基数或敏感标签风险，立即停用新标签，恢复上一白名单；资源原始账继续保留。
5. 切换回旧账本时以资源总账为基准，输出事件账、分配账、财务账三方差异报告。
6. 恢复门禁：总额守恒、幂等无重复、真实患者字段零出现、账期冻结结果可复算。
