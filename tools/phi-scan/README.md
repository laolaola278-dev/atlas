# Atlas `phi-scan` 设计说明

> **当前角色**：隐私安全负责人 / 测试架构师
> **本章产出**：真实患者数据检测架构、规则、误报控制、CI fail-closed 契约
> **依赖的上游产出**：`plan/_contract.md`、ADR-012、ADR-025、ADR-031

## 1. 目标与红线

`phi-scan` 在提交、构建、测试数据发布和制品扫描阶段检测疑似 PHI/PII。命中即阻断，不允许用提示词说明或人工口头确认绕过。工具本身不得把完整命中值打印到日志；只输出规则、路径、行号、哈希和最小必要掩码。

## 2. 检测范围

扫描：源码、测试、fixture、示例、Markdown、JSON/YAML、SQL、CSV、截图 OCR 文本、前端存储样本、日志样本、压测数据和模型评测数据。默认跳过依赖锁文件、编译缓存和已验证的公开术语词表，但跳过项必须出现在报告中。

## 3. 检测引擎

| 层 | 方法 | 示例 | 结果 |
|---|---|---|---|
| 确定性标识 | 中国大陆身份证、手机号、银行卡、医保/住院号 | 结构化校验和校验位 | 高置信阻断 |
| 区域标识 | 统一社会信用代码、国际患者标识等 | 正则 + 校验和 | 高置信阻断 |
| 联系信息 | 邮箱、手机号、住址 | 规则 + 上下文 | 邮箱单独可配置；组合命中阻断 |
| 医疗语境 | 病历号、诊断、检验、处方等与姓名/日期组合 | 词典 + 邻近窗口 | 组合命中阻断 |
| 敏感词 | 真实机构、患者姓名、罕见病情的候选词典 | 哈希化受控词典 | 人工复核或阻断 |
| 熵检测 | 长随机串、密钥、Base64、十六进制数据 | Shannon entropy + 字符类 | 仅在高风险上下文阻断 |
| DICOM/HL7 | 标签头与结构段 | 解析器 + 字段白名单 | 身份段出现即阻断 |
| OCR | 截图、扫描件 | OCR + 上述规则 | 识别置信度不足时隔离复核 |

正则只做候选召回；身份证、银行卡等使用校验位，日期使用合法日历校验，避免纯正则误判。

## 4. 上下文与熵模型

高熵本身不证明是 PHI，因此熵检测只与路径/字段上下文联合判定：

```text
risk = identifier_score
     + 0.8 * medical_context_score
     + 0.6 * contact_context_score
     + 0.4 * high_entropy_score
     + config_weight(path)
```

阈值需使用**纯合成**标注集校准，不得从生产患者数据学习。发布前用 1,000 个以上合成/公开安全样本和至少 200 个内部安全 fixture 验证误报；真实生产数据不得进入回归集。

## 5. 配置与排除

```yaml
version: 1
failOn:
  - verified-identifier
  - phi-context-combo
  - dicom-identity
  - hl7-identity
reviewOn:
  - high-entropy
  - name-plus-clinical-context
allow:
  - scope: testdata
    reason: "RFC 示例"
    owner: privacy-lead
    expires: "2026-12-31"
    sha256: "exact-file-digest"
```

禁止通配整个目录、禁止永久排除、禁止用 `.phiignore` 自行绕过。例外必须绑定文件摘要、责任人、理由和到期日；过期自动失败。

## 6. 输出契约

```json
{
  "schema_version": "1.0",
  "revision": "git-sha",
  "status": "pass",
  "scanned_files": 0,
  "blocked_findings": 0,
  "review_findings": 0,
  "findings": [
    {
      "rule": "cn-id-verified",
      "path": "test/fixture/example.json",
      "line": 1,
      "fingerprint": "sha256:...",
      "masked": "**********************",
      "confidence": 1.0
    }
  ],
  "skipped": []
}
```

报告不包含原始命中值。确需人工复核时，通过权限受控的隔离流程查看，CI 报告只保留指纹。

## 7. CI 集成

1. pre-commit：对暂存文本和图片运行快速扫描。
2. pull request：全仓扫描 + 变更基线；不降低历史基线。
3. main/release：全仓、二进制字符串、解包资源和制品层扫描。
4. 压测数据发布：必须通过 `synthetic_provenance` 签名；来源不明直接失败。
5. 工具异常、规则文件损坏、无法读取受检文件时一律失败（fail-closed）。

## 8. 误报与对抗

- 公共测试标识、虚构患者和哈希值使用合成命名空间。
- 对 Unicode 同形字、全角字符、Base64、URL 编码、JSON 转义做规范化后再匹配。
- 防止攻击者用拆分字符串规避：词法层拼接普通字符串常量后再次扫描。
- 对压缩包、Parquet、Arrow、图片 EXIF、DICOM 私有标签做解包扫描。
- 规则命中不可由普通 PR 作者单独豁免，须隐私负责人审批。

## 9. 验收标准

| 测试 | 通过标准 |
|---|---|
| 合成验证标识 | 校验位合法样本 100% 检出 |
| 标点/全角/转义变体 | 规范化后检出率 ≥ 99% |
| 公共代码与术语 | 误报率 < 0.1%（安全合成集） |
| 任意篡改/删行 | 阻断或进入复核，无静默放行 |
| 规则文件损坏 | CI 失败，不降级为空扫描 |
| 例外过期 | 自动阻断 |
| 报告脱敏 | 不出现完整标识符 |
| 大仓性能 | 在 P8 目标硬件实测；当前容量标 `[待验证]` |
